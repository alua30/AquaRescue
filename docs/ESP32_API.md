# AquaRescue — контракт API между ESP32 и Android-приложением

Версия контракта: **1** (`api_version: 1`)

Документ фиксирует формат обмена данными между прошивкой спасательного жилета
(ESP32 WROOM) и Android-приложением AquaRescue. Приложение реализовано строго по
этому контракту (`app/src/main/java/com/aquarescue/app/network/`). Прошивка ESP32
должна реализовать перечисленные ниже эндпоинты.

---

## 1. Транспорт

| Параметр            | Значение                                                       |
|---------------------|----------------------------------------------------------------|
| Протокол            | HTTP/1.1, без TLS (локальная сеть)                             |
| Формат              | JSON, `Content-Type: application/json; charset=utf-8`          |
| Кодировка           | UTF-8                                                          |
| Порт по умолчанию   | `80`                                                           |
| IP по умолчанию     | `192.168.4.1` (ESP32 в режиме точки доступа, SoftAP)           |
| Модель обмена       | Приложение опрашивает ESP32 (polling), по умолчанию раз в 1 с  |
| Таймауты клиента    | соединение — 2,5 с, чтение — 3 с                               |

### Режимы сети ESP32

1. **SoftAP (рекомендуется)** — ESP32 создаёт собственную Wi-Fi-сеть
   (например, `AquaRescue-01`), телефон подключается к ней. Адрес ESP32 — `192.168.4.1`.
   Интернета в такой сети нет; приложение само направляет запросы через Wi-Fi,
   даже если Android считает сеть «без доступа к интернету».
2. **STA** — ESP32 подключается к существующему роутеру. IP-адрес выдаёт роутер
   (DHCP); его нужно ввести в настройках приложения (ESP32 выводит IP в Serial Monitor).

## 2. Эндпоинты

| Метод | Путь          | Назначение                                     |
|-------|---------------|------------------------------------------------|
| GET   | `/api/status` | Текущая телеметрия: глубина, GPS, SOS, датчики |
| GET   | `/api/info`   | Информация об устройстве (проверка связи)      |
| POST  | `/api/sos`    | Активация / отмена SOS из приложения           |
| POST  | `/api/sound`  | Включение / отключение звука (DFPlayer, buzzer)|

---

### 2.1. `GET /api/status`

Основной эндпоинт. Вызывается периодически.

**Ответ 200:**

```json
{
  "api_version": 1,
  "device_id": "aquarescue-01",
  "uptime_ms": 734512,
  "depth": {
    "valid": true,
    "depth_m": 0.42,
    "pressure_mbar": 1054.3,
    "temperature_c": 18.6
  },
  "gps": {
    "valid": true,
    "fix": true,
    "lat": 43.640120,
    "lon": 51.120450,
    "satellites": 7,
    "hdop": 1.2,
    "age_ms": 850
  },
  "sos": {
    "active": false,
    "source": "none",
    "since_ms": 0
  },
  "audio": {
    "muted": false,
    "dfplayer_ok": true,
    "buzzer_on": false
  },
  "sensors": {
    "ms5837": "ok",
    "gps": "ok",
    "dfplayer": "ok",
    "mic": "ok",
    "sos_button": "ok"
  },
  "wifi": {
    "mode": "ap",
    "rssi": -58,
    "ip": "192.168.4.1"
  },
  "alarm": "NORMAL"
}
```

**Описание полей:**

| Поле                    | Тип     | Описание |
|-------------------------|---------|----------|
| `api_version`           | int     | Версия контракта. Приложение поддерживает `1`. |
| `device_id`             | string  | Идентификатор жилета. |
| `uptime_ms`             | long    | Время работы ESP32 с момента включения, мс (`millis()`). |
| `depth.valid`           | bool    | `false`, если MS5837 не инициализирован или вернул ошибку. |
| `depth.depth_m`         | float   | Глубина, м. Считается на ESP32: `(P − P_surface) / (ρ·g)`, P_surface калибруется при включении. Отрицательные значения ограничиваются `0`. |
| `depth.pressure_mbar`   | float   | Абсолютное давление, мбар (GY-MS5837-30BA). |
| `depth.temperature_c`   | float   | Температура воды, °C (встроенный датчик MS5837). |
| `gps.valid`             | bool    | `true`, если координаты `lat/lon` хотя бы раз были получены. |
| `gps.fix`               | bool    | `true` — фиксация есть **сейчас**; `false` — нет сигнала (например, под водой). |
| `gps.lat`, `gps.lon`    | double  | Последние известные координаты (WGS-84, градусы). Передаются, даже если `fix=false`. |
| `gps.satellites`        | int     | Число спутников (NEO-6M / TinyGPS++). |
| `gps.hdop`              | float   | Горизонтальный фактор точности. |
| `gps.age_ms`            | long    | Возраст координат, мс (`gps.location.age()`). |
| `sos.active`            | bool    | SOS активен. |
| `sos.source`            | string  | `none` \| `button` (кнопка на жилете) \| `app` (из приложения). |
| `sos.since_ms`          | long    | Сколько мс SOS активен. |
| `audio.muted`           | bool    | Звук DFPlayer / buzzer отключён. |
| `audio.dfplayer_ok`     | bool    | DFPlayer Mini отвечает. |
| `audio.buzzer_on`       | bool    | Buzzer сейчас звучит. |
| `sensors.*`             | string  | `ok` \| `error` \| `absent` \| `no_fix` (только `gps`). |
| `wifi.mode`             | string  | `ap` или `sta`. |
| `wifi.rssi`             | int     | Уровень сигнала, дБм (в режиме STA; в AP можно передать `0`). |
| `wifi.ip`               | string  | IP ESP32. |
| `alarm`                 | string  | Необязательная оценка тревоги на стороне ESP32: `NORMAL` \| `WARNING` \| `DANGER`. |

**Правила совместимости:**

- Приложение **игнорирует неизвестные поля** — прошивка может добавлять новые.
- Отсутствующие необязательные поля считаются неизвестными (не нулём).
- Обязательные поля: `api_version`, объект `depth`, объект `gps`, объект `sos`.
- При несовместимом изменении формата увеличивается `api_version`.

### 2.3. `POST /api/sos`

**Запрос:**

```json
{ "action": "activate", "request_id": "6f1c2a0e-…", "source": "app" }
```

| Поле         | Значение |
|--------------|----------|
| `action`     | `activate` — включить SOS; `cancel` — отменить. |
| `request_id` | Уникальный ID запроса (UUID). ESP32 обязан вернуть его в ответе. |
| `source`     | Всегда `app`. |

**Ответ 200 (подтверждение):**

```json
{ "ok": true, "request_id": "6f1c2a0e-…", "sos_active": true }
```

**Правило подтверждения.** Приложение считает SOS отправленным **только** если:
1. HTTP-код 200;
2. `ok == true`;
3. `request_id` совпадает с отправленным;
4. `sos_active` соответствует запрошенному действию.

Во всех остальных случаях пользователю показывается ошибка, а в истории
фиксируется событие «SOS не подтверждён». Повторная отправка — по кнопке.

При активации SOS прошивка должна: включить buzzer, воспроизвести голосовое
сообщение через DFPlayer (если звук не отключён), выставить `sos.active=true`,
`sos.source="app"`.

---

### 2.4. `POST /api/sound`

**Запрос:**

```json
{ "muted": true }
```

**Ответ 200:**

```json
{ "ok": true, "muted": true }
```

Приложение показывает новое состояние только после ответа с `ok == true`.

> Примечание: отключение звука не должно отключать buzzer при активном SOS —
> это решение прошивки (рекомендуется для безопасности).

---

## 3. Ошибки

Любая ошибка возвращается с кодом 4xx/5xx:

```json
{ "ok": false, "error": "invalid_json" }
```

| Код | `error`            | Когда |
|-----|--------------------|-------|
| 400 | `invalid_json`     | Тело не JSON |
| 400 | `invalid_action`   | Неизвестное значение `action` |
| 404 | `not_found`        | Неизвестный путь |
| 500 | `sensor_error`     | Внутренняя ошибка |

## 4. Поведение приложения при потере связи

| Ситуация | Поведение |
|----------|-----------|
| 1 неудачный запрос | Статус «Переподключение…», данные остаются, но помечаются временем последнего обновления |
| Нет данных > 6 с | Статус **CONNECTION_LOST**, событие в истории, звуковое оповещение (если включено) |
| Повторные попытки | Экспоненциальная задержка 1 → 2 → 4 → 8 → 10 с (максимум) |
| Связь восстановлена | Событие «Соединение восстановлено», статус пересчитывается |

## 5. Логика тревоги (приложение)

| Состояние | Условие |
|-----------|---------|
| `CONNECTION_LOST` | Нет данных от ESP32 дольше 6 с |
| `DANGER` | SOS активен **или** глубина ≥ порога опасности (по умолчанию 1,5 м) **или** погружение ≥ порога предупреждения дольше заданного времени (по умолчанию 15 с) **или** ESP32 сообщил `alarm: DANGER` |
| `WARNING` | Глубина ≥ порога предупреждения (по умолчанию 0,5 м) **или** неисправен датчик глубины/GPS **или** ESP32 сообщил `alarm: WARNING` |
| `NORMAL` | Иначе |

Пороги настраиваются в приложении (Настройки → Пороги тревоги).

## 6. Проверка без оборудования

В каталоге `tools/` находится эмулятор ESP32 на Python (`esp32_mock_server.py`),
реализующий этот контракт. Он нужен только для проверки сетевого слоя и
**не является** реальным устройством. См. `README.md`.

Эталонный скетч прошивки, совместимый с контрактом, — `firmware/aquarescue_esp32/aquarescue_esp32.ino`.
