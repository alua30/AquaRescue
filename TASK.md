# ЗАДАНИЕ: ПОЛНАЯ РАЗРАБОТКА ANDROID-ПРИЛОЖЕНИЯ AQUARESСUE

Ты выступаешь в роли опытного Android-разработчика, UI/UX-дизайнера и инженера IoT.

Твоя задача — самостоятельно разработать полноценное Android-приложение AquaRescue для моего учебного дипломного проекта.

ВАЖНО: ты работаешь непосредственно с файлами проекта на моём компьютере через Claude Code. Не ограничивайся предоставлением примеров кода или инструкций. Самостоятельно создавай и редактируй необходимые файлы, настраивай зависимости, запускай сборку и исправляй ошибки.

## 1. Информация о проекте

Название: AquaRescue.

Назначение: мобильное приложение для интеллектуального спасательного жилета.

Проект состоит из двух частей:
- аппаратное устройство на ESP32;
- Android-приложение AquaRescue.

Приложение должно получать данные от ESP32 через локальную сеть Wi-Fi.

Используемые компоненты:
1. ESP32 WROOM CH340.
2. GY-MS5837 30BA — датчик давления для определения глубины.
3. NEO-6M — GPS-модуль.
4. DFPlayer Mini — воспроизведение аудио.
5. MAX9814 — усилитель микрофонного сигнала.
6. SOS-кнопка.
7. Active Buzzer.
8. Динамик 8 Ohm 2W.

Все компоненты уже приобретены, но аппаратная сборка ещё не начата.

## 2. Технологический стек

Используй:
- Kotlin;
- Android Studio;
- Jetpack Compose;
- Material 3;
- Navigation Compose;
- Coroutines;
- StateFlow;
- ViewModel;
- Retrofit или Ktor только при необходимости;
- Google Maps SDK только если его настройка действительно доступна. Не требуй платного API для базовой работы приложения.

Выбирай стабильные совместимые версии библиотек.

Минимальная версия Android — Android 8.0 (API 26), если это совместимо с выбранными зависимостями.

## 3. Дизайн приложения

Создай современный, профессиональный и реалистичный интерфейс для приложения мониторинга спасательного оборудования.

Стиль: Dark Marine UI.

Основные цвета:
- фон: тёмно-синий или почти чёрный;
- основные элементы: насыщенный синий;
- нормальное состояние: зелёный;
- предупреждение: оранжевый;
- аварийное состояние: красный;
- основной текст: светлый;
- вторичный текст: серый.

Требования к дизайну:
- единый стиль на всех экранах;
- аккуратные отступы;
- одинаковые радиусы карточек;
- современные иконки;
- читаемая типографика;
- отсутствие чрезмерных градиентов;
- отсутствие лишних декоративных элементов;
- адаптация под разные размеры экранов;
- интерфейс должен выглядеть как настоящее коммерческое приложение, а не демонстрация возможностей ИИ.

Не используй случайные изображения и декоративные элементы, не связанные с проектом.

## 4. Необходимые экраны

### Экран 1. Главная

Создай основной экран со следующими элементами:

1. Логотип и название AquaRescue.
2. Статус подключения ESP32.
3. Индикатор Wi-Fi.
4. Карточка текущей глубины.
5. Карточка GPS-координат.
6. Большой круговой индикатор глубины.
7. Карточка состояния системы.
8. Кнопка SOS.
9. Кнопка управления звуком.
10. Переход к карте.

На главном экране вся важная информация должна быть видна без лишней прокрутки на обычном смартфоне.

### Экран 2. Карта

Создай экран GPS-мониторинга.

Необходимо отображать:
- последние известные координаты;
- широту;
- долготу;
- время последнего GPS-обновления;
- статус GPS-сигнала.

Предусмотри корректное состояние, когда GPS недоступен.

ВАЖНО: GPS NEO-6M не получает спутниковые координаты под водой. Приложение должно явно показывать последние известные координаты, а не выдавать их за актуальные.

### Экран 3. История

Создай экран истории событий.

Отображай:
- дату и время;
- изменение глубины;
- GPS-обновления;
- нажатия SOS;
- предупреждения;
- потерю соединения.

Предусмотри пустое состояние, когда событий ещё нет.

### Экран 4. Настройки

Добавь:
- подключение к ESP32;
- IP-адрес устройства;
- порт подключения;
- проверку соединения;
- настройки звуковых уведомлений;
- информацию об устройстве;
- версию приложения.

## 5. Подключение к ESP32

Реализуй архитектуру взаимодействия приложения с ESP32 через локальную сеть Wi-Fi.

Предусмотри:
- подключение к IP-адресу ESP32;
- получение данных о глубине;
- получение GPS-координат;
- получение статуса SOS;
- получение состояния датчиков;
- обработку потери соединения;
- автоматическое восстановление соединения;
- отображение времени последнего обновления данных.

Предложи простой HTTP REST API или другой подходящий способ обмена данными.

Сначала разработай понятный контракт API и зафиксируй его в документации проекта. Предусмотри совместимость с будущей прошивкой ESP32.

Не придумывай, что реальное оборудование уже подключено.

## 6. Режим демонстрации

Поскольку аппаратная часть ещё не собрана, реализуй отдельный демонстрационный режим.

В демонстрационном режиме:
- показывай тестовые значения глубины;
- показывай тестовые GPS-координаты;
- демонстрируй изменение состояния системы;
- позволяй проверить интерфейс;
- позволяй имитировать SOS.

Обязательно визуально обозначай, что данные демонстрационные.

Не смешивай тестовые значения с реальными данными датчиков.

Предусмотри возможность отключить демонстрационный режим после подключения ESP32.

## 7. Логика аварийной сигнализации

Предусмотри следующие состояния:
- NORMAL;
- WARNING;
- DANGER;
- CONNECTION_LOST.

Кнопка SOS должна:
- запрашивать подтверждение ручной отправки сигнала;
- отправлять команду ESP32 при подключении;
- показывать результат отправки;
- обрабатывать ошибки.

Не заявляй, что SOS отправлен, если ESP32 не подтвердил получение команды.

Предусмотри отображение аварийного события в истории.

## 8. Архитектура проекта

Используй понятную структуру:

- data;
- domain;
- presentation;
- ui;
- navigation;
- network;
- model.

Раздели интерфейс, бизнес-логику и получение данных.

Не помещай весь код в MainActivity.

Используй ViewModel и StateFlow для управления состояниями интерфейса.

Добавь обработку ошибок и пустых состояний.

## 9. Самостоятельная реализация

Работай по следующим этапам:

Этап 1. Проанализируй существующую папку проекта и её структуру.

Этап 2. Проверь настройки Gradle и зависимости.

Этап 3. Разработай архитектуру приложения.

Этап 5. Реализуй все четыре экрана.

Этап 6. Добавь навигацию.

Этап 7. Реализуй демонстрационный режим.

Этап 8. Реализуй сетевой слой для ESP32.

Этап 9. Добавь историю событий и сохранение необходимых данных локально.

Этап 10. Добавь обработку ошибок и состояний подключения.

Этап 11. Запусти сборку проекта.

Этап 12. Исправь все ошибки компиляции, которые можешь воспроизвести.

Этап 13. Проверь, что приложение можно запустить на Android-эмуляторе.

## 10. Качество результата

Не создавай только визуальный макет.

Нужно полноценное Android-приложение с работающей навигацией, демонстрационными данными, состояниями интерфейса и подготовленным сетевым взаимодействием.

Не используй фиктивные подтверждения подключения к ESP32.

Не оставляй кнопки без действий.

Не устанавливай ненужные библиотеки.

Не удаляй существующие файлы без необходимости.

Перед выполнением опасных команд запрашивай разрешение.

Если какая-либо функция требует API-ключа или дополнительной настройки, сообщи об этом и реализуй доступную альтернативу.
